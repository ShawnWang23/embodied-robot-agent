# 简历项目经历：室内机器人长程任务执行 Agent

## 推荐版（适合具身智能 / Agent / 机器人软件岗位）

### 室内机器人长程任务执行 Agent｜ROS2 + LangGraph + Nav2 + YOLO｜2026.11

**项目简介：** 面向室内巡检与多地点导航任务，搭建“自然语言指令—结构化规划—机器人执行—视觉感知—异常恢复—人工接管”的闭环 Agent 系统；通过工具白名单、地点目录和状态机约束 LLM 行为，避免坐标幻觉及直接下发速度指令。

**我的职责：** 负责系统架构设计与核心功能落地，完成以下模块：

- **Agent 编排与安全规划：** 基于 LangGraph 构建 `plan → validate → create_task → execute` 工作流，使用 Pydantic Structured Outputs 校验任务计划；设计 Tool Registry 与语义地点目录，仅开放导航、状态查询、图像采集和目标检测 4 类结构化动作，在进入机器人执行层前拦截未知地点、非法参数和未注册工具。
- **任务执行与闭环恢复：** 设计 MissionManager 与显式 FSM，支持多步骤任务的执行、暂停、恢复、取消、超时及单机器人互斥；对导航阻塞、目标不可达、工具及感知失败进行确定性分类，实现有限重试、显式备用观察点和 `waiting_for_human` 降级，恢复前强制确认机器人与环境状态，防止进程重启后盲目重放动作。
- **ROS2 与多模态感知：** 封装统一 RobotAdapter，接入 ROS2 Nav2 `NavigateToPose`、`/odom` 反馈和主动 Goal 取消；通过 `cv_bridge` 获取 640×480 相机图像，使用 YOLO 完成目标检测，并根据结构化检测结果进入 `objects_detected / clear` 条件分支。
- **持久化服务与评测：** 使用 SQLite 分离保存任务快照、结构化事件和 LangGraph checkpoint，基于 FastAPI 提供任务提交、查询、控制、事件与历史 checkpoint 等 9 条接口；构建 10 类场景、40 次可复算的软件故障注入基准，保存 JSONL 原始记录及汇总报告。

**项目成果：** 当前环境回归测试 **54 项全部通过**，核心模块分支覆盖率 **87.56%**；10 类场景、40 次标准故障注入的预期行为 **40/40 匹配**，20 次触发恢复的任务中 **16 次自动恢复成功**；在同一 Gazebo Waffle 实例中完成 Nav2、1920×1080 Camera、YOLO 与闭环重规划验收，共执行 7 步、3 个导航 Goal 均一次成功，并完成 SiliconFlow 三地点在线规划验收。

> 面试口径：40 次基准是确定性软件故障注入，不表述为 40 次真机实验；93.75% 的感知 Precision/Recall 来自合成标注链路验证，不表述为公开数据集模型精度。

## 一页简历精简版

### 室内机器人长程任务执行 Agent｜ROS2、LangGraph、Nav2、YOLO、FastAPI、SQLite

- 面向室内巡检任务搭建“自然语言规划—多步骤执行—视觉感知—异常恢复”闭环，基于 LangGraph、Pydantic Structured Outputs、Tool Registry 与地点目录约束 LLM，只允许 4 类结构化动作进入机器人执行层。

## 建议优先补强的项目项

1. **形成可审查的 Git 作品集（最高优先级）：** 当前仓库尚无提交记录。补充规范化 commit、远程仓库、License、版本 tag、架构图和一条从零复现的命令；配置 GitHub Actions 执行 pytest、Ruff、类型检查和覆盖率报告。
2. **扩大统一 Gazebo 闭环样本：** 单次同栈验收已经完成；下一步至少运行 30 次不同 seed / 障碍布局实验，报告成功率、P95 时延与恢复次数。
3. **把局部重规划扩展为任务级闭环：** 当前已支持感知结果审查、备用观察点局部重规划和双重预算；下一步增加多轮状态观测、任务级反思/重规划及可恢复 checkpoint 节点。
4. **完善指标可信度与对照实验：** 区分 FakeRobot、Gazebo、真机三层指标；加入无恢复策略、无结构化校验等 baseline，对比任务成功率、平均恢复次数、P95 时延和 LLM 调用成本。感知部分使用自采或公开标注集评估 Precision / Recall，而非只用合成样本。
5. **强化运行时与数据一致性：** 将进程内后台任务升级为持久化任务队列/单机器人调度器；为提交接口增加幂等键，为任务状态增加乐观锁；SQLite 开启 WAL 并引入 schema migration，避免多进程下重复执行和快照覆盖。
6. **补齐生产安全与可观测性：** 增加 API 鉴权、限流、CORS 白名单、LLM 超时/重试/熔断与成本追踪；接入结构化日志、Prometheus 指标和 OpenTelemetry trace，贯通 thread、task、step、Nav2 goal 与模型调用。
7. **提升演示说服力：** 当前演示主要是信息卡片。建议录制 Gazebo/RViz、API 请求、LangGraph trace、任务事件和失败恢复的分屏视频，并准备 2–3 分钟讲解稿，直观展示“发生故障—有限恢复—请求人工—安全续跑”的完整过程。
